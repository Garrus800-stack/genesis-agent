## [7.9.33]

Genesis changes — graph, memory, schemata, fitness — but until now no organ held on to what changed. Gains are visible because they exist; losses were invisible unless witnessed in the moment of disappearing. This release adds the change register: a passive Phase-9 sibling of the event counter that writes one append-only journal line per change event — never pruned, never read on the runtime path, reachable only through a new slash command. Six sources feed it. Both knowledge-graph prune paths now announce themselves with up to twenty node identities and a cause tag: the cap eviction enriches its existing event, and the stale sweep — previously the largest silent loss path in the system, with three production callers — fires for the first time. Schema pruning carries the names of what fell. The two memory releases and the consolidation each carry a label, so a journal line stays readable on its own even after the memory behind it decays or is replaced. And the register is the first listener the fitness evaluation broadcast has ever had: pure record, no reaction — the open genome question stays open and will be decided later from the real distribution these lines accumulate.

Witness durability is staged by event weight. The storage append gains a backward-compatible opt-out of its fsync guarantee, and the register uses it for exactly one line kind: the hot-path cap eviction, which can fire once per node insertion at the cap. Everything deliberate — releases, consolidations, schema and stale prunes, fitness — keeps the full crash-safe guarantee. Coherence argument: the graph itself persists debounced, so an fsync-hard witness line about an eviction whose graph consequence a crash would swallow anyway would be false precision. Two payload-schema drifts of the same shape were corrected along the way: schema-pruned and memory-consolidated both declared a count field that was never fired while their real fields went undeclared; both declarations now state the truth.

Documentation was brought current in the same release. The persistence layout now lists all eleven `.genesis` journals including the register and the flight recorder; EVENT-FLOW gained an additions section with the register witness diagram and the enriched event truths; SECURITY documents the v7.9.30 shell-origin enforcement and hardening base; SKILL-SECURITY describes the Können forged-skill maturity model; the gate inventory covers all nineteen scripted gates; the quick-start command table carries the full 25-command slash surface with the flight-recorder wording; SETTINGS documents `sandbox.readScope` and the two-key rule; and the deep-dive, communication, capabilities, architecture-history, and Phase-9 documents each gained the observation-layer and change-witness coverage.

The register is deliberately bounded: consolidation merge-victims are not journalised (absorption is not disappearance — a cause tag is the prepared additive path if the field ever shows the gap hurts), goal outcomes stay with the event counter, no affect echo, no rotation. Two guardrail contracts pin that register contents never reach the prompt or the identity summary — readable through /changes alone, which routes with the established slash discipline and answers honestly on an empty journal. One new source module and one new contract suite with nineteen pins across durability, all six line forms, batch behaviour on both prune paths, the staged hardness, both guardrails, and the complete slash triangle — 419 modules, 616 test files.

The release that gives Genesis a memory for change also gives it a face. The new mark — a ring, a core, and two clock hands frozen at 21:26, the moment of the first boot on the 2026 March equinox — ships as `docs/mark.svg` and as a multi-size `build/icon.ico` wired into the window, so Genesis appears in the taskbar under its own sign. Ring and core carry the banner's blue, the hands its gold: identity data as geometry, stable because the moment is.
