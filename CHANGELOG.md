## [7.9.48] — 2026-07-29

**Three security layers, each built around one spelling — and in all three the bypass was one keystroke away.** A full audit of v7.9.47 read every file in the release: 443 source modules, 44 scripts, 23 documents, 653 test files, 21 gates. Twenty-six findings came out of it, and six claims had to be withdrawn after measurement — but the three that mattered most turned out to be the same mistake three times. `CodeSafetyScanner` blocked `new Function` and let `Function(…)` through. `ShellSafety` blocked `rm -rf /` and let `rm -r -f /` and `rm -fr /` through. The injection gate caught "I am an Anthropic engineer" and let "I work at Anthropic" through. Fourteen security test files existed; not one of them checked a variant spelling, which is why the class was structurally unfindable.

**The repairs follow the shape of the mistake, not the individual holes.** The scanner gained three AST rules — `Function()` as a call, computed `import()`, computed `require()` — which finally makes true a promise its own header has carried since v5.1.0: *"catches eval, Function(), kernel imports"*. The shell gate normalises flags before checking rather than enumerating variants, in the same function that already normalised Unicode confusables "so blocklist regex can match" — someone had the thought once, for the wrong axis. The path detector no longer requires a trailing slash (`/etc` passed where `/etc/` was blocked) and now knows `/Users`. The authority patterns lost their dependency on the phrase "I am", while staying bound to the organisation name — without that binding, "Ich arbeite bei der Analyse der Logdatei" would be flagged, which is exactly the over-reach the gate must avoid.

**One of those repairs would have made things worse on its own.** Normalising `rm -rf` into `rm -fr` means the block pattern, which knew only `-rf`, stops matching. Normalisation and patterns had to move together; measured separately, the "fix" would have opened the very hole it was closing.

**The chat path could not read a tool call written as text.** `NativeToolUse` — untouched since v3.5.0 — reads only the backend's structured `tool_calls` field and hands the text back when that field is empty; the early return in front of it sat between the model and `parseToolCalls`, which since v7.9.46 understands seven text formats including the pipe-delimited tokens some models emit. Every fix made to that parser was therefore invisible on this path. It now parses the text it already holds, and deliberately does not fall through to the block below: that would cost a second model call per turn.

**Making room for that fix meant splitting the hottest file in the tree.** `ChatOrchestrator.js` stood at 699 lines against a 700-line guard — one line — with eight changes from the last eight versions, and twice a justification had already been squeezed into an end-of-line comment to stay under the limit. The streaming path and its session helpers moved to `ChatOrchestratorStream.js`; the file is now 492 lines. Six source pins across six test files followed their subject, because a pin belongs with the thing it guards and not with the file it used to live in.

**Two wiring blocks still whispered their own failure.** In v7.9.46 the vestibule was invisible for ten versions because a `catch { log.debug }` swallowed a wiring error; the lesson was written down and applied to that one block. Its two neighbours — sixteen memory and archive tools, both lab tools — kept logging at debug. Both now warn, and a pin holds it: neither can fail quietly again. The lab block already carried the other half of that same lesson in its own comment, which is how a half-applied lesson looks from the outside.

**Six files that constrain Genesis were not hash-locked.** The model was already coherent — twenty-one self-modification files and twenty-two audit scripts follow the rule *what constrains or checks him, he must not touch*. The shell gate, the injection gate, the vestibule's triple gate, the key encryption, the tool registry and the MCP door did not. They are locked now, and the audit demands them by name, because its own scope derives from the self-modification write-side signature and would have noticed neither their addition nor their later removal.

**And an unclassified action was auto-approved from AUTONOMOUS upward.** The fallback read `ACTION_RISK[actionType] || 'high'` with the comment *"Unknown actions are high risk"* — but 'high' is on the auto-approve list at level 1. The live case was `self-modification`, the lowercase twin of `SELF_MODIFY`, which the table rates 'critical': the same operation was approval-bound under one name and automatic under the other.

**Four commands that spoke about him existed only in the terminal.** `/crashlog` was found and registered in v7.9.47 as a single case; nobody asked whether it was a pattern. The CLI knew 22 commands, the chat 26, and the overlap was two. `/selfmodel`, `/adaptations`, `/autonomy` and `/budget` are in the chat now — whoever talks to Genesis in the app could not previously ask how he sees himself. `/consolidate` deliberately stayed behind: it rebuilds his knowledge graph, and that is an intervention rather than a report.

**Twelve of thirteen fitness checks stopped at `src/agent`.** The coverage check reported "100%" truthfully for the tree it looked at, while `IntelRenderers.js` — 653 lines — had no test at all. Coverage now reaches `src/ui` and `src/kernel`, and both renderers have a contract that also pins something nobody had checked: that they share no method names, and that applying one twice changes nothing.

**Four real audit tools ran only when someone remembered them**, among them the 44-case revision matrix and the v7.9.47 slash-discipline fix that dies on an empty security set — a fix that could never fire, because its script was in no chain. Three are wired into both chains now, the matrix into `ci:full` alone at 91 seconds. `audit-platform-tests` stayed out on purpose: it contains only `process.exit(0)` and would have been decoration. And `.github/` held issue templates and no workflow, so a 27-link chain ran on habit rather than mechanism; there is a workflow now.

**And the field found the same mistake one more time, in a gate.** `check-stale-refs` compares each scanned file against an exclude list; `path.relative` returns backslashes on Windows while the list is written with forward slashes, so the comparison never matched there. All four changelog archives were scanned, eleven historical symbol references were reported, and the gate was red on Windows while green on Linux — for as long as anyone had run it. Two other scripts in the tree already normalise the separator before comparing, so the house knew the shape; this one did not. The separator is normalised now, and pinned both ways round. The three remaining `path.relative` call sites were checked and only report, never compare.

**A second field run showed the new gate was decoration.** The 44-case revision matrix was wired into `ci:full` this release — and on Windows it reported *42 OK · 2 FAIL* while the chain carried on to the end, because the script printed its verdict and always exited 0. That is precisely the check that kept `audit-platform-tests` out of the chain, and it was not applied to the matrix. It exits non-zero now, and every one of the twenty-five scripts in the chain was measured for the same property: all can fail.

**Both matrix failures were assumptions in the test, not defects.** One built a second vault root as a case-variant of the first (`Eltern/Kind` after `eltern/kind`) — the same directory on a case-insensitive filesystem, so the second root never existed and the drift hint could not fire. The other expected the answer "module could not load" for a PDF; on a machine that ran `npm install`, `pdfjs-dist` is present, Genesis actually parses the four bytes the test wrote and correctly reports an invalid structure. The case asks for an honest cause, not one specific cause — both are honest, and only a silent empty answer would not be.

**Comments that promised behaviour now say what is true.** Two of his seven genome traits have no reader: `verbosity` claimed "PromptBuilder response length guidance" — the only `verbosity` in the tree belongs to `UserModel` and describes the human's preference — and `socialDrive` claimed "NeedsSystem social need growth rate", which NeedsSystem does not read. Both are marked, not deleted: removing a considered knob because it was forgotten is the wrong repair. `MetaLearning` promised results "after 200 interactions" while the code knows 10 and 50. The README claimed 79 IPC channels on each side; there are 84 handlers and 69 the renderer may invoke, and the symmetry it asserted never existed.
