## [7.9.30]

This release closes the one real security gap an audit of 7.9.29 surfaced, ships the two audit-tool fixes that had blocked a clean tag, and adds a guard for the guards so the kind of validator blindness that produced those two fixes cannot recur silently. A symlink placed inside the project could point a file read at a secret outside it; the read gate and the chat file reader now judge a path by its real target, while still reading a legitimate file under a project directory that itself sits under a symlink. The set of always-blocked secret files grows to cover the credential and certificate formats the audit found uncovered. Reading a named file understands a directory path and a trailing verb, a dead helper is removed, and the stale-reference guard runs in the pipeline. A live run of the release also surfaced a cluster of chat-execution issues, fixed here in the same version: a skill that is not found no longer runs the chat text as a shell command, a slash-command is recognised only when it starts the message, identical tool calls repeated within one response run once, the skill-invocation lines the prompt teaches are executed rather than left inert, every shell command now declares where it came from so one that arrives without a known origin is refused before it runs, and a sentinel left by a test-boot is no longer read as a crash.

### A symlink can no longer read past the project boundary

The read gate resolved a path textually and compared it to the project root, so a symlink inside the project that pointed at a file outside it — a key, an environment file — passed the boundary check and was read. The gate now resolves the real target of a path before judging it, and canonicalises the project root the same way, so an in-root link that escapes is caught while a genuine file inside a project directory that is itself reached through a symlink — a temporary directory on macOS, a synced folder — still reads and is not thrown out. A path that does not yet exist is judged by its canonicalised parent, so a read or create of a new file under such a root stays portable. The chat file reader, which enforces the secret and system blocks itself, re-checks the resolved target immediately before reading, so a link with an innocent name cannot carry a read to a protected file. The always-blocked secret set adds the netrc, known-hosts, PostgreSQL-password, Java-keystore, and certificate formats; the npm configuration file was already covered on the system-path side.

### The wiring audits, and a guardian for them

A 7.9.29 split moved a registration call into a companion module and renamed the file that held it; two audits that read the source by a hardcoded file name went blind, one reporting a wired class as unregistered and the other missing an intent, though both resolved at runtime. Each audit is corrected to read both halves of the split. Because the failure was not in the code but in the audits' own sight, a new self-test now stands guard over them: it requires every wired module, so a file that passes a syntax check but throws at load — the shape of a bad edit that leaves a removed name referenced — is caught in the pipeline rather than at boot, and it confirms every source path a validator hardcodes still resolves to a real file, so a rename or delete cannot leave a validator pointing at nothing. The size guard, which fails past nine hundred lines and warns past seven hundred, now also names the files that have crossed six hundred and fifty, as an informational heads-up that does not change the score.

### Reading a named file understands paths and a trailing verb

The direct read of a named file recognised a plain filename; a request that named a file by its directory path, or that placed the verb after the name — "read src/agent/AgentCore.js", "can you show me README.md" — fell through to the chat model. Both forms now resolve to the same bounded read, scoped to a real filename with an extension so an unrelated phrase does not match, and a question about whether a file was already read stays conversational.

### Chat-execution hygiene

A live run of the release drove a short chat exchange that exposed how model output could reach the wrong executor. A skill invoked by name that did not exist used to fall back to running the whole chat message as a shell command; that fallback is gone, and a name that is not found now returns a clean error and, where a close match exists, suggests the nearest installed skill — by meaning when the request describes intent, and by name similarity when it is a typo. Slash-command discipline, which decided whether a message may carry a command at all, keyed on a slash anywhere in the text; it now keys only on a slash that starts the message, so a pasted log line or a copied command inside a longer question routes to an ordinary answer instead of a command, while a genuine command that opens the message — with or without leading spaces — still routes. When a model repeats the same tool call several times in one response, the identical calls now collapse to a single execution, and the synthesis step is told a collapse happened so it does not re-issue them; this covers the primary tool-call channel as well as the fence and skill-line channels, at the point where all three have merged. The skill-invocation lines the prompt teaches — a slash form with an optional JSON argument — are now parsed from model output into real tool calls, so a model that follows the taught format runs instead of emitting text nothing acts on. A sentinel written during a test-boot is tagged as such, and a boot running under test treats a leftover sentinel as a clean start, so the test harness no longer reports a crash from a prior run's un-cleaned file.

### Every shell command declares its origin

Removing the skill-fallback closed one way model output could reach a shell; to make that whole class of gap fail loudly rather than quietly, the shell agent now requires every command to carry a declared origin — where it came from: a path the user named in chat, the model tool-loop, the autonomous loop, or a test harness. A command that arrives without a known origin is refused before it runs and recorded as a blocked command, so a forgotten call site, or a future silent path of the kind the fallback had been, surfaces at once instead of executing unprovenanced; the requirement doubles as its own sweep check, since an un-updated caller shows up immediately as blocked. The chat axis stays the one that lifts the sandbox scope restriction, behind the absolute system and secret blocks that always hold — the added origins label provenance only, and neither widen what a command may reach nor reopen the read-to-act path that stays closed by design. A test harness declares its origin once through the agent it constructs rather than at each call, and the read-only fence and the shell tool run through a separate executor with its own safety, so the requirement is scoped precisely to the commands that flow through the shell agent.

### Housekeeping

A dead similarity helper is removed from the capability matcher — the active measure is the term-frequency cosine, and the helper had no caller outside its own test — while the identically named private helper elsewhere is untouched. The stale-reference guard, which pins deleted symbols and required contract counts, now runs as a pipeline step, and two contract families it had flagged as unregistered are recorded.
